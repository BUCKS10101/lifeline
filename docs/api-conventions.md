# API conventions

These rules apply to every backend endpoint. They describe what the code does today or must do from Phase 1 on.

## URLs and versioning

- All endpoints live under `/api/v1`.
- Resource names are plural, lowercase and kebab-case: `/api/v1/workout-templates`.
- Nested resources only when the child cannot exist without the parent: `/api/v1/workouts/{id}/sets`.
- Actions that are not plain CRUD use a verb sub-path with POST: `/api/v1/workouts/{id}/finish`.
- A breaking change means a new version prefix (`/api/v2`), not an edit to `/api/v1`.

## Methods and status codes

| Method | Use | Success |
|--------|-----|---------|
| GET | Read, never changes state | 200 |
| POST | Create or run an action | 201 with `Location` header for creates, 200 for actions |
| PUT | Replace a resource | 200 |
| PATCH | Partial update | 200 |
| DELETE | Remove | 204, no body |

| Status | Meaning |
|--------|---------|
| 400 | Malformed request or failed validation |
| 401 | Not authenticated |
| 403 | Authenticated but not allowed |
| 404 | Not found, and also used when the resource belongs to another user (do not reveal that it exists) |
| 409 | Conflict, such as a duplicate email |
| 429 | Rate limited |
| 500 | Unexpected server error |

## Requests and responses

- JSON only. `Content-Type: application/json`.
- Field names are camelCase.
- Dates are ISO 8601. Timestamps are UTC with a `Z` suffix (`2026-09-24T10:15:30Z`). Calendar dates without a time are `YYYY-MM-DD`.
- IDs are UUIDs, generated by the backend.
- Weights are in kilograms and distances in metres. The API never accepts unit-suffixed strings.
- Enums are UPPER_SNAKE_CASE strings (`IN_PROGRESS`).
- JPA entities are never returned. Every endpoint uses request and response DTOs.
- Responses return the resource directly, with no `{ "data": ... }` wrapper.

## Errors

Every error uses the `ApiError` body from `common/error`:

```json
{
  "timestamp": "2026-09-24T10:15:30Z",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "message": "Request validation failed",
  "path": "/api/v1/tasks",
  "violations": [
    { "field": "title", "message": "must not be blank" }
  ]
}
```

- `code` is a stable, machine-readable UPPER_SNAKE_CASE string. Clients branch on `code`, never on `message`.
- `violations` is empty unless the error is a validation failure.
- Stack traces, SQL and internal class names never appear in a response. Unexpected errors return `INTERNAL_ERROR` and are logged server-side.

## Pagination, sorting and filtering

- List endpoints that can grow without bound are paginated: `?page=0&size=20`. Default size 20, maximum 100.
- Paged response:

```json
{ "items": [], "page": 0, "size": 20, "totalItems": 0, "totalPages": 0 }
```

- Sorting: `?sort=createdAt,desc`. Only whitelisted fields are accepted.
- Filters are plain query parameters, such as `?status=DONE&from=2026-09-01&to=2026-09-30`.
- Date ranges are inclusive on both ends.

## Authentication and ownership

- Every endpoint except health and the auth endpoints requires authentication.
- Every user-owned resource is looked up by both its ID and the current user's ID. Ownership is enforced in the service layer, never only in the frontend.
- Mutating requests from a browser are protected against CSRF (defined in Phase 1).

## Idempotency and safety

- GET, PUT and DELETE are idempotent.
- POST endpoints that trigger side effects, such as sending email or syncing external data, accept an `Idempotency-Key` header so retries do not repeat them.
- Rate limits return 429 with a `Retry-After` header.

## Layering

Controller, service, repository, entity, DTO and mapper stay separate within each module. Controllers handle HTTP only, services own business rules and transactions, and repositories own queries.
